# ADR 0001 — SORI × Ara 통합: IR 중심 범용 코어 (v0.3.0a1)

- 상태: **제안 (Proposed)** — PR 리뷰·CI 통과 전까지 `main` 미반영
- 날짜: 2026-10-27
- 관련: Issue #2, 브랜치 `integration/ara-sori-unified-core`, 기준 커밋 `33bdbd3` (Phase B1)

## 1. 맥락

| | SORI B1 (`main`) | Ara 제안 (`proposal/v0.2-merge`) |
|---|---|---|
| 언어 | 선언형 JSON API DSL (route/input/return/invoke) | 범용 언어 (변수·함수·람다·반복·레코드·테스트) |
| 실행 | 화이트리스트 AST 해석, **코드 생성 없음** | 파이썬 소스 생성 후 `compile()`/`exec()` (제한 `__builtins__`) |
| 중간 표현 | Typed IR v1 (결정적 JSON, 워커 URL 제외) | 없음 (파이썬 코드가 사실상 IR) |
| 강점 | 감사 용이, OpenAPI 3.1, 정적 타입 검사, Rust 경로(B2) | 표현력, 보안 기본값(sql/html/권한/SSRF), AI 도구, 배포 생성기, 한국어 진단 |

두 원칙이 정면으로 충돌했다: **B1 은 ".sori 를 파이썬으로 실행하지 않는다"**, Ara 는 **"파이썬으로 생성해 exec 한다"**.
제한된 `__builtins__` 와 속성 차단은 컴파일 타임 방어일 뿐 OS 수준 격리가 아니며, 생성 코드에 의존하면 IR → Rust 경로(B2)가 끊긴다.

## 2. 결정

1. **프런트엔드는 Ara 를 채택**한다 (렉서·파서·AST·스코프/불변성/권한/라우트 정책/HTML 문맥 검사, 한국어 진단).
2. **Ara 의 파이썬 코드 생성과 `exec` 를 폐기**하고, 컴파일러 출력을 **버전형 Typed IR v2 (`sori/ir/v2`)** 로 바꾼다.
3. 실행은 IR 위에서만 한다.
   - **Python Backend**: IR 해석기 (`sori/framework/interp.py`). `eval`/`exec`/`compile` 없음, 속성 화이트리스트, 실행 상한.
   - **Rust Backend (B2 슬라이스)**: `runtime-rs/` 의 std 전용 IR 해석기. 지원하지 않는 IR 은 501 로 거부.
4. **B1 은 삭제하지 않고 v0.1 DSL 경로로 그대로 유지**한다 (`sori/compiler.py`, `runtime.py`, `typed_ir.py`, `openapi.py` 무수정). CLI 는 파일 첫 줄이 `app "..."` 이면 B1 동작을 그대로 수행한다. 새 문법으로의 이동은 `sori migrate`.
5. **IR v1 은 v0.1 DSL 전용으로 동결**, 통합 언어는 IR v2. v1 은 파이썬 `ast` 모양에 묶여 있어 범용 언어를 담을 수 없기 때문이다.
6. 보안 기본값은 기존보다 약화하지 않는다.
   - `strict_inputs` 기본 켜짐 (범위 없는 외부 입력 = 컴파일 오류)
   - 운영에서 끌 수 없음
   - `use py` 는 개발 전용 (운영 기동 거부)
   - 워커는 인증된 라우트에서만 (B1 규칙, 함수 호출 그래프까지 추적)
7. 버전은 `0.3.0a1` 로 한다 (`0.2.0a1` 은 B1 이 사용 중).

## 3. 검토한 대안

| 대안 | 내용 | 기각 이유 |
|---|---|---|
| A′. Ara 그대로 병합 (exec 유지) | 제안 브랜치 그대로 | B1 불변 원칙 위반, B2 Rust 경로 단절, 샌드박스 보장 불가 |
| B. 트랙 분리 | DSL 은 main, Ara 는 별도 실험 언어 | 언어가 둘로 갈라지고 보안 정책·도구가 중복 |
| C. B1 DSL 에 기능 이식 | DSL 에 sql/html/guard 를 하나씩 추가 | 범용 언어 수준까지 장기간 소요, 정규식 기반 파서의 확장 한계 |
| **A. IR 중심 재구성 (채택)** | Ara 프런트엔드 + IR v2 + 해석기 백엔드 | 두 원칙(코드 미실행·범용 표현력)을 동시에 만족, Rust 백엔드로 같은 IR 실행 가능 |

## 4. 결과와 비용

**좋아지는 점**
- 런타임 경로에 동적 코드 실행이 없다 (AST 검사 테스트 + CI grep 가드).
- 같은 IR 을 Python·Rust 가 실행하고, 테스트 벡터 20건에서 결과가 일치한다 (정수/실수 구분 포함).
- IR 에 타입·접근 정책·입력 계약·효과(effects)·권한 다이제스트·소스 위치가 담겨 OpenAPI, 감사, AI 도구가 같은 원천을 쓴다.
- B1 테스트 29개가 무수정으로 통과하고, v0.1 → v0.3 마이그레이션의 응답 동등성을 23개 요청으로 검증했다.

**비용 (실측)**
측정 조건: 같은 프로그램, 같은 머신, 레이트 리밋 끔, p50.

| 작업 | 기존 exec 방식 | IR 해석기 | 배수 |
|---|---|---|---|
| GET /api/todos (20행 JSON) | 160µs | 307µs | 1.9× |
| GET / (HTML 렌더) | 221µs | 821µs | 3.7× |
| 로봇 `step()` (CPU 위주) | 3.4µs | 64µs | ~19× |

→ 웹 요청은 수용 가능한 수준이고, 50Hz 제어 루프(20ms 예산)에도 충분하다. 다만 CPU 집약 코드는 느리다. 개선 경로는 IR → 클로저 사전 변환(여전히 exec 없음)과 B2 Rust 백엔드다.

**받아들이는 제약**
- 통합 언어는 v0.1 DSL 문법을 직접 실행하지 않는다 (B1 경로 + `sori migrate` 로 대체).
- `use py` 는 개발 전용이 되어 robot 예제에서 numpy 를 제거했다.
- Rust 백엔드는 슬라이스 범위만 지원한다 (std 모듈·사용자 함수·guard 미지원 → 501).

## 5. 검증되지 않은 것 (이 ADR 이 주장하지 않는 것)

- 외부 침투 테스트, 퍼징, 형식 검증은 하지 않았다. IR 해석기는 **OS 수준 격리가 아니다**.
- Docker 이미지 빌드는 데몬 없는 환경이라 미실행이다 (생성물 정적 검증만 함).
- CI(GitHub Actions)는 PR #3 에서 3.12·3.13 모두 통과했다. 다만 이 작업 환경에서는 CI 로그 본문을 내려받을 수 없어, CI 안의 테스트 개수·skip 여부는 단계 결과(전부 success)로만 확인했다.
- Rust 백엔드의 성능·메모리 이점은 측정하지 않았다.
